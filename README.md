# Рейтинг игроков Аист-4

Программа раз в сутки забирает с rfll.ru календарь команды и протоколы матчей, считает баллы игроков
и обновляет страницу рейтинга. Работает бесплатно на GitHub, компьютер включать не нужно.

## Установка (один раз, около 30 минут)

1. Зарегистрируйтесь на https://github.com.
2. Нажмите «New repository». Имя: `aist4-rating`, тип: Public. Нажмите «Create repository».
3. Нажмите «uploading an existing file» и перетащите в окно все файлы и папки из архива.
   Папка `.github` скрытая: если она не загрузилась, создайте файл вручную через
   «Add file → Create new file», имя `.github/workflows/update.yml`, и вставьте текст
   из одноименного файла архива.
4. Settings → Pages → Source: «Deploy from a branch», ветка `main`, папка `/docs` → Save.
5. Settings → Actions → General → Workflow permissions: «Read and write permissions» → Save.
6. Вкладка Actions → «Обновление рейтинга» → «Run workflow».
   Через 1-2 минуты страница откроется по адресу `https://ВАШ_ЛОГИН.github.io/aist4-rating/`.

Дальше обновление идет само каждый день в 08:00 по Москве.
Запустить вручную можно той же кнопкой «Run workflow».

## Лучший игрок матча

Пока бот ВКонтакте не подключен, итог опроса вносится в файл `data/mvp.csv`
(на GitHub: открыть файл, значок карандаша, «Commit changes»). Одна строка на матч:

```
match_id,player
39158,Овсянников
```

`match_id` это число из адреса протокола (rfll.ru/match/39158), `player` это фамилия
как в протоколе или номер игрока с rfll.ru.

## Матчи Кубка

Страница команды без параметров показывает только текущий турнир (сейчас Чемпионат),
а страницы с параметрами правила сайта закрывают для программ. Поэтому номера кубковых
матчей вносятся в `data/cup_matches.csv`, по одному на строку:

```
match_id
39201
```

Номер берется из адреса протокола. Все остальное (счет, составы, соперник) программа
заберет сама. Матчи Чемпионата, попавшие в список один раз, сохраняются в
`data/our_matches.json` и не пропадут, даже когда на странице команды сменится турнир.

## Сезоны

На странице рейтинга есть переключатель сезонов: «Все сезоны», «Сезон 2026», «Сезон 2026-2027», «Сезон 2027». Выбранный сезон запоминается в браузере. Режим «Все сезоны» суммирует матчи всех сезонов. Внутри любого режима работают прежние фильтры Чемпионат, Кубок, Все турниры, а карточка игрока показывает статистику за выбранные сезон и турнир.

Сезон матча определяется по его дате. На сайте лиги даты указаны без года, поэтому год подбирается по правилу: берется последняя такая дата, не позднее завтрашнего дня. Найденная дата сохраняется в data/our_matches.json и больше не меняется.

Границы сезонов по умолчанию:

- Сезон 2026: с 01.01.2026 по 15.10.2026;
- Сезон 2026-2027: с 16.10.2026 по 31.03.2027;
- Сезон 2027: с 01.04.2027 по 31.12.2027 (дата начала условная).

Чтобы изменить границы или добавить сезон, впишите в config.yaml раздел (даты в формате ГГГГ-ММ-ДД):

```
seasons:
  - {key: "2026", title: "Сезон 2026", start: "2026-01-01", end: "2026-10-15"}
  - {key: "2026-2027", title: "Сезон 2026-2027", start: "2026-10-16", end: "2027-03-31"}
  - {key: "2027", title: "Сезон 2027", start: "2027-04-01", end: "2027-12-31"}
```

Если программа не смогла определить дату матча или определила ее неверно, укажите дату вручную в файле data/match_dates.csv (столбцы match_id и date, например 38217,29.05.2026). Ручная дата имеет приоритет. Такие матчи программа перечисляет в предупреждениях.

Ожидаемые голы соперника для бонуса вратаря считаются отдельно по каждому сезону. Пока в новом сезоне мало сыгранных матчей (меньше 10), в качестве среднего по лиге берется среднее по всем сезонам. Порог меняется параметром goalkeeper.min_league_games в config.yaml.

## Настройки

Все веса баллов, названия турниров и параметры вратаря находятся в `config.yaml`.
Код менять не нужно.

## Если что-то не так

Откройте Actions → последний запуск → шаг `python main.py`. Строки «ВНИМАНИЕ» объясняют,
что не получилось. Если сайт лиги изменит верстку, какие-то данные перестанут распознаваться:
пришлите эти строки, и парсер подстроим.

# Бот ВКонтакте

Бот запускается каждый час вместе с рейтингом и работает от имени сообщества (club241645516):

- распознает афиши с расписанием, которые пересылают в беседу команды или в личные сообщения
  сообществу (капитан и помощники), находит матч команды и просит капитана подтвердить его
  (нет ответа 12 часов: спрашивает помощников), после подтверждения объявляет игру в беседе;
- если афиши нет, берет дату и время с сайта лиги;
- после появления протокола публикует в беседе сводку матча и просит капитана выбрать лучшего игрока
  (48 часов; затем голосование помощников 24 часа; затем по баллам за матч);
- первого числа каждого месяца публикует итоги прошедшего месяца.

## Шаг 1. Ключ сообщества

Сообщество → Управление → Работа с API → Ключи доступа → «Создать ключ», отметьте
«Разрешить приложению доступ к сообщениям сообщества», подтвердите и скопируйте ключ.

## Шаг 2. Как бот получает афиши

Ключей для этого не нужно. Достаточно переслать пост лиги с расписанием (или саму картинку):

- в беседу команды: бот прочитает ее сам, если сообщество назначено администратором беседы;
- или в личные сообщения сообществу: так могут делать капитан и помощники, бот ответит,
  сколько матчей команды нашел на афише.

## Шаг 3. Секреты в GitHub

Settings → Secrets and variables → Actions → «New repository secret»:

- `VK_GROUP_TOKEN`: ключ сообщества.

Секреты `VK_USER_TOKEN` и `VK_SERVICE_TOKEN`, если они остались, не нужны.

## Шаг 4. Проверка ключей и номер беседы

Actions → «Обновление рейтинга» → «Run workflow», режим «проверка ключей». В журнале шага
«Бот и рейтинг» будет список бесед с номерами. Впишите номер беседы команды в `config.yaml`,
параметр `chat_peer_group`.

## Шаг 5. Проверка чтения беседы

В журнале «проверки ключей» (после того как номер беседы вписан в `config.yaml`) должна быть строка
«Сообщения беседы команды читаются». Если написано «НЕ читаются», назначьте сообщество
администратором беседы и повторите проверку.

## Шаг 6. Пробный запуск

Режим «пробный»: бот ничего не отправит и не сохранит, а в журнале покажет, что сделал бы.
После этого все работает само, раз в час.

## Важно для капитана и помощников

Каждый из них должен один раз написать сообществу в личные сообщения любое слово.
Без этого ВКонтакте не разрешает сообществу писать человеку первым.
